Market Radar — local run checklist
Checked 21 November 2026. Full setup and capabilities: README.md.

REQUIREMENTS
Node.js 24.9+ and npm. Tested local workflow: Windows PowerShell.
SQLite is built into Node. No database service or local Docker is required.
The approved 0.6.0-local data package is supplied separately and is not in Git.

FIRST RUN (from the repository root)
1. npm ci
2. npm run data:prepare -- "<path-to-approved-release-directory>"
   Required: manifest.json, market-radar-public-ch.sqlite,
   capabilities-public-ch.json and capabilities-regional-ch.json.
   Preparation verifies and copies saved files; it does not download sources.
3. npm run data:verify
4. If .env.local does not exist, copy .env.example to .env.local.
   Preserve an existing file. Set OPENAI_API_KEY locally to enable the analyst,
   or leave it empty for manual analytics. OPENAI_MODEL is configurable;
   the default is gpt-6.1-terra. Never commit the key.
5. npm run build
6. npm start
7. Open http://127.0.0.1:3000 (redirects to /overview).

DEVELOPMENT
Use npm run dev instead of steps 5–6. Stop a process already using port 3000
before starting another. Stop the local production server before rebuilding
its .next output. npm start loads .env.local, copies static assets into the
standalone build and binds to loopback. Fonts are served locally.

CHECKS
npm run data:verify
npm run typecheck
npm test
With the app running: npm run test:api

The current deterministic suite has 76 tests and uses mocked AI responses.
Bare Node helpers do not automatically load .env.local. If an offline helper
needs optional path variables, set them in the shell or load the file explicitly:
  node --env-file=.env.local scripts/verify-data.mjs
An HTTP QA helper uses the running server's AI configuration, not a client key.
On Windows, retain trusted system CAs for direct HTTPS checks:
  node --use-system-ca scripts/check-production.mjs
That comparison requires both local and production services. Real-provider
helpers are listed in docs/VALIDATION.md and may incur API charges.

DATA AND HISTORY
Public analytics: data/market-radar.sqlite, read-only.
Private conversations: .runtime/conversations.sqlite, writable and Git-ignored.
Active scope: 10 datasets, 595 series and 3,445 numeric observations;
168 series and 2,015 observations are national. These are not unique job counts.
Thurgau vacancy data is excluded; other sources' Thurgau canton slices remain.
Source coverage and verification meaning: docs/DATA.md.

History belongs to the browser cookie, not a user account or physical device.
Tabs sharing a cookie share history. Separate profiles and local/production hosts
have separate histories. The cookie lasts 24 hours and is renewed on session
responses; server inactivity expiry is 48 hours. Clearing cookies loses access.
At least 20 follow-ups are supported, with earlier exact results retrievable by
a tool. Unsent drafts survive page navigation, not reload. Decision context is
saved before the first question; Use chart only clears it persistently.
New conversation switches sessions without immediately deleting the old rows.

TROUBLESHOOTING
- Missing data / unhealthy: install the approved package and run data:verify.
- Wrong archive version or hash: obtain the approved package; do not bypass checks.
- Port in use: stop the existing project server or choose another PORT.
- AI unavailable: check the server key/model and provider access with one question.
  Manual analysis remains usable; health "configured" only means a key exists.
- Loading failure: use the visible retry after the 10-second load deadline.
  Retain TLS verification; browser/server logs can distinguish failure causes.
- Rate limit: allow the one-minute window to clear before repeating a QA suite.
