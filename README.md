# Market Radar

An evidence-led workspace for Powercoders to understand the Swiss IT labour market. Explore data manually or ask the AI Analyst to find indicators, run the same deterministic calculations, and explain the results with charts, sources and limitations.

**[Open the live MVP](https://hackatonprojekt.net)** · Documentation checked **21 November 2026**.

The interface is English; the analyst can answer in the user's language. The app serves a **frozen, reviewed dataset**, not a live feed or a census of Swiss vacancies.

## Explore the workspace

| Page | What it does |
| --- | --- |
| [Market overview](https://hackatonprojekt.net/overview) | Six separate signals covering platform skills, industry vacancies, occupational advertisements, registered vacancies and participant context |
| [Graduate opportunities](https://hackatonprojekt.net/opportunities) | Investigate 35 published national role tags, with separate junior, whole-sample technology and official industry panels |
| [Participant context](https://hackatonprojekt.net/participants) | SEM F, refugee B and S populations: separately sourced working-age counts, employment counts and rates for Switzerland and all 26 cantons |

| [Explore the market](https://hackatonprojekt.net/explore) | Filter by source, indicator, geography, dates and measure; use history, snapshots, compatible rankings and underlying tables |
| [AI Analyst](https://hackatonprojekt.net/analyst) | Ask free-form questions, retrieve evidence through seven typed tools, and continue with at least 20 follow-ups |
| [Sources & coverage](https://hackatonprojekt.net/sources) | Check publisher links, observation periods, retrieval/review dates and limitations |

The manual dashboard and AI share one analytics engine. A question can update the working chart; a manual chart or decision brief can become the starting point for a conversation. Charts use backend results, never values generated by the model. Compare is offered only for compatible alternatives; unsupported comparisons have an explanation rather than a disabled menu of unusable options.

Try: “What data do we have?”, “How has Python changed?” → “Compare with Docker”, or “What should we investigate before changing the programme?” From Participant context, select a group and canton, choose **Ask about this brief**, then ask “What about Bern?” See the [three-minute demo](DEMO.txt).

## What the data supports

Release **`0.6.0-local`**, source policy **`2026-11-21.1`**: **10 datasets, 595 series and 3,445 observations**. National coverage comprises **168 series and 2,015 observations**. These are stored measurements, including related counts and shares, not unique job advertisements. Review dates do not imply that all observations are current.

| Challenge area | Implemented scope and boundary |
| --- | --- |
| A — Demand | ITBoard role/junior signals and complementary BFS, Eurostat and SECO context. No complete Swiss IT-vacancy total or graduate-suitability score. |
| B — Skills | Named-skill snapshots/trends from **ITBoard only**. No verified role × named skill × time or junior × skill intersection. |
| C — Employers | No company-level outreach directory or employer recommendations backed by named hiring records. |
| D — Target group | SEM F, refugee B and S context for ages 18–64, nationally and by canton, at **31 October 2026**. No origin breakdown, trend, IT-sector placement rate or programme outcomes. |
| E — Policy | A small saved evidence collection includes a dated provisional SECO notice. There is no current-law verification or automated policy watch. |

Selected HSLU research notes are available as cited evidence. Get U Hired research rows are excluded from numeric analysis. The **Thurgau vacancy dataset** is excluded; other publishers' observations for the canton of Thurgau remain available. Different populations and definitions cannot be added into a single market total.

[Data coverage and verification](docs/DATA.md) lists all datasets, periods, capabilities and release requirements. Scheduled collection, email reports, employer/candidate matching, forecasting and source addition through a config-only UI are not implemented.

## Run locally

Use **Node.js 24.9+** and npm; local verification uses Windows PowerShell and production uses Linux ARM64. SQLite is built into Node, so no separate database service or local Docker setup is required.

**A clean clone does not include the dataset.** Obtain the separately supplied approved release directory with `manifest.json`, `market-radar-public-ch.sqlite`, `capabilities-public-ch.json` and `capabilities-regional-ch.json`. Preparation verifies and copies those files; it does not download sources.

```powershell
git clone https://github.com/ivanslavinskyi/hackaton.git
cd hackaton
npm ci
npm run data:prepare -- "<approved-release-directory>"
npm run data:verify
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

Set `OPENAI_API_KEY` in `.env.local` to enable the analyst. Leave it blank for manual analytics. The configured default model is `gpt-6.1-terra`; `OPENAI_MODEL` can override it. Keep keys on the server and out of Git. Model access must be checked with a real question; a configured key alone does not establish provider availability.

```powershell
npm run build
npm start
```

Open [http://127.0.0.1:3000](http://127.0.0.1:3000). For development use `npm run dev` instead. Stop the existing process on the chosen port before starting another; stop the local production process before rebuilding its output. Fonts are self-hosted and need no external font service.

| Variable | Purpose / default |
| --- | --- |
| `OPENAI_API_KEY` | Server-side credential; optional for manual analytics |
| `OPENAI_MODEL` | Responses API model; default `gpt-6.1-terra` |
| `MARKET_RADAR_DATA_DIR` | Prepared serving files; defaults to project `data/` |
| `MARKET_RADAR_SESSION_DB` | Writable history file; defaults to `.runtime/conversations.sqlite` |
| `PORT` | Local server port; defaults to `3000` |
| `MARKET_RADAR_RELEASE_DIR` | Input directory for `data:prepare`; an explicit command argument takes precedence |

`data:prepare` always writes to project `data/`; provision a different runtime directory separately. Bare Node helper scripts do not automatically load `.env.local`; see [local run notes](RUN-LOCAL.txt) for verification and troubleshooting.

## History, context and shared links

History is stored **server-side**, with access tied to an anonymous HTTP-only cookie in that browser profile. Separate browsers/profiles have separate histories; tabs using the same cookie share a conversation. Local and production history are independent. There are no accounts, cross-device synchronization or account-based recovery.

The cookie lasts 24 hours and is renewed on session responses; the backend has a sliding 48-hour inactivity lifetime. Clearing cookies or starting a new conversation removes access to the previous conversation from that browser. Starting anew switches to a new session; it is not a deletion of the old stored rows. Capacity is bounded at 100 questions per conversation and 100 active conversations.

Original turns and exact results support the initial question plus at least 20 follow-ups. Recent context and a compact ledger enter the prompt; a tool retrieves older originals when needed. This is not a promise that every long or ambiguous question will be interpreted correctly.

Switching pages preserves the draft and ongoing analysis. Reload restores saved history and selected context, but not an unsent draft or an interrupted request. Decision handoffs are saved **before the first AI question**. **Use chart only** and explicit manual handoffs clear the previous role/group/canton context persistently. Shared URLs contain public filters, never private questions or conversation IDs. [Routing details](docs/ROUTING.md).

## Verify

With the approved data installed:

```powershell
npm run data:verify
npm run typecheck
npm test
npm run build
```

With the app running, use `npm run test:api`. On Windows, direct Node HTTPS checks use the workstation's trusted certificates:

```powershell
$env:MARKET_RADAR_TEST_URL = "http://127.0.0.1:3000"
node --use-system-ca scripts/smoke-api.mjs
node --use-system-ca scripts/check-production.mjs
```

The second command compares local and public production data and requires configured AI keys on both hosts, but does not call the model. The current suite has **76 passing tests**. Browser checks and real-provider checks are separate; the 20-follow-up automated test uses a mock provider. See [Validation](docs/VALIDATION.md) for commands, latest acceptance, rate limits and billable checks. Private test reports stay out of Git.

## Architecture, design and operations

Next.js App Router, React, TypeScript, Tailwind CSS, Recharts and Zod run as one Node service. A read-only SQLite file holds the public dataset; a separate writable SQLite file holds conversations. The analyst has typed tools, bounded calls/tokens, validated citations and source-backed views. It cannot execute arbitrary SQL or generated code. Manual analytics remains available when the model is unavailable.

The live service uses one native ARM64 Docker container behind Caddy HTTPS, with persistent history, read-only data, health checks and resource/log limits. The current application release is **`20261121-brand`**, application commit **`3817a3b`**. Documentation-only commits do not rebuild that image. [Deployment](docs/DEPLOYMENT.md) records current paths, safe updates, backup and rollback; scheduled backups, off-host copies and CI/CD are not configured.

The [design system](docs/DESIGN-SYSTEM.md) follows the supplied Figma palette: red, teal, mint and neutral surfaces; Bebas Neue for display text, Roboto for reading/data and Inter for controls. Font licences and source hashes are included.
